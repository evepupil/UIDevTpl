| 项目 | 内容 |
| --- | --- |
| 模块定位 | 提供分类发现、固定版本预览、分享者与互动展示、模板包分发和迁移指令生成能力 |

## 职责与边界

- 展示、搜索、筛选和排序已经发布的模板实现。
- 提供首页 Category 预览、分类总览和单分类结果。
- 展示分享者名称、头像、浏览量和点赞，并为社区投稿保留统一目录条目。
- 管理网站 Light / Dark、中文 / English 偏好和账号能力入口。
- 提供固定版本详情、内嵌预览、独立预览和组件实验室入口。
- 从同一模板记录生成页面、下载信息和 AI 迁移指令。
- 维护固定包、校验值、缓存、SEO、匿名统计和紧急下架入口。
- 不读取用户项目，不远程执行用户项目构建，不提供完整项目脚手架。

## 结构与数据流

```text
app.js 中的原型数据
  -> Category / 分享者 / 浏览量 / 点赞
  -> 首页 / 分类总览 / 单分类页 / 详情弹窗
  -> 主题、语言和能力预留反馈

生产阶段：模板源码与 Manifest
  -> 发布门禁
  -> 固定版本记录与模板包
  -> 模板列表 / 详情 / 预览 / 迁移指令
  -> 用户交给 AI 在本地迁移
```

## 关键决策

- 平台、框架、组件库和模板组成四段式 ID。
- V1 公开 React 模板统一使用 `shadcn` 作为 `library` 段；长期继续保留该维度，为其他组件体系提供独立实现。
- 页面、预览、模板包和迁移指令绑定同一固定版本。
- 预览使用独立来源或严格 sandbox，网络访问采用白名单。
- `withdrawn` 从公开入口移除，固定页保留最小事故记录。
- 生产技术栈、版本基线、构建和部署边界以 [技术架构与构建](./技术架构与构建.md) 为准。
- 主站使用 Next.js App Router，独立预览使用 Vite MPA；二者分别部署为 Vercel Project。
- 官网使用站点自有 shadcn/ui 组件源码；模板分别拥有自己的 shadcn/ui 源码，双方不共享运行时 UI 包。
- 旧原型继续暂存无构建的静态 HTML、CSS 和 JavaScript，只用于盘点既有行为和提供回退依据，不再作为生产迁移或视觉基准。
- 旧原型数据与交互留在 `prototype/data.js` 和 `prototype/app.js`，新设计确认并建立替代门禁后整体删除。
- 模板产物与目录条目分开建模，分类、分享者和热度变化不会污染固定模板版本。
- 账号、投稿和持久化点赞由能力开关控制；关闭时保留导航、路由与数据契约。
- 网站主题独立于模板主题，网站切换 Dark 不代表 `blackline-saas` 支持 Dark 模板实现。

## 主站视觉状态

主站的新视觉和信息架构以[主站体验重设计](./主站体验重设计.md)为准。`UIDevTpl Signal Desk` 已退出现行设计，当前没有已确认的新视觉基线。

- Impeccable 的 `PRODUCT.md` 已完成，记录产品用户、目的、定位和能力边界。
- 新页面布局、视觉语言、色彩、字体、密度和标志性交互将在 `shape` 与 `new-work` 中讨论。
- 方向确认前不删除旧 UI，不创建 `DESIGN.md`，也不从旧 CSS 提取新设计系统。
- shadcn/ui preset、Base UI、Lucide 和主站/模板运行时隔离属于技术基线；最终视觉使用方式由新设计决定。

## 当前实现

当前可直接打开的旧低保真交互原型覆盖以下行为，但不再代表目标布局与视觉：

- 首页发现工作台、精选系统、用途索引、最新系统和迁移流程。
- 模板库关键词、用途、实现方式和排序筛选，以及空状态。
- 用途目录、系统详情抽屉、Showcase / 组件 / Tokens / 迁移页签。
- 桌面、平板、手机预览尺寸切换，分享、登录和独立预览预留反馈。
- 心形点赞、明暗主题、中英文切换、迁移指令复制和移动端菜单 / 筛选面板。
- `prototype/browser-smoke.cjs` 使用本机 Edge 验证主要交互与 390px 无横向溢出。

`@uidevtpl/catalog` 已把目录条目、Category、分享者、指标、Showcase、组件清单和迁移指令字段收口为版本化开发 fixture。`prototype/` 继续作为主站低保真原型；`apps/web` 已实现首页、模板库、分类总览、单分类、最新/固定版本详情、使用说明和登录/注册/投稿预留路由。当前 Catalog 首个条目已切换为 `web/react/shadcn/blackline-saas`，`apps/preview` 通过固定深链展示 Overview、Billing 和组件实验室。下载地址、SHA-256、固定发布产物、Registry Item、持久化互动、匿名统计、SEO 和完整双 Project 发布链路仍未形成公开生产证据。主站与预览的既有部署记录属于旧草稿验收，不能继承到 Blackline SaaS。

## 验证方式

- 运行格式化、静态分析、类型检查、单元测试和生产构建。
- `packages/catalog/src/index.test.ts` 覆盖目录筛选、固定版本路由、Showcase 固定预览路径和迁移指令身份绑定。
- 主站与预览站分别通过 TypeScript 检查和生产构建；完整模板门禁继续由首个模板模块单独推进。
- 验证官网与模板没有共享运行时 UI 包，`library=shadcn` 的目录、路由、预览、ZIP 和 Registry Item 使用同一固定身份。
- 验证固定 URL、缓存、SHA-256、下载失败和紧急下架流程。
- 在规定浏览器与视口检查预览隔离、交互、无障碍和 Core Web Vitals。
- 验证匿名统计不包含用户业务需求和项目数据。
- 当前原型通过 `pnpm run check:prototype` 和 `pnpm run test:prototype` 检查语法、主要交互与 390px 横向溢出；新实现完成后替换这些门禁。
