# 第二视觉家族

| 项目 | 内容 |
| --- | --- |
| 模块定位 | 为公开 V1 提供与 Blackline SaaS 明显不同的第二套完整视觉选择 |
| 对应代码 | 待命名的家族目录与 `packages/templates/web/` 下的实现目录 |
| 所属 M 里程碑 | [M3](../roadmap.md#m3) |
| 当前状态 | 未开始 |
| 最近更新时间 | 2026-08-11 |

## 职责与边界

- 定义独立的颜色、字体、密度、形状、构图和内容规则。
- 使用真实源码提供组件实验室、两个 Showcase 和三类页面骨架。
- 证明模板库提供真实的风格选择，禁止依靠 Blackline SaaS 浅层换色交付。
- V1 只要求一个完整 Web / React / shadcn/ui 实现，具体 shadcn style 与底层组件基础在设计启动前锁定。

## 结构与数据流

```text
第二家族视觉方向
  -> 家族契约与资产规则
  -> Web 模板实现
  -> 预览与固定模板包
  -> 独立发布门禁
```

## 关键决策

- 第二家族必须与 Blackline SaaS 在密度、形状、字体、色彩和主要构图上形成清楚差异。
- 仍然遵循 V1 核心组件、固定版本、MIT 代码授权和迁移门禁。
- 不能借用 Blackline SaaS 的预览图或用自动换色结果替代独立实现。
- V1 与 Blackline SaaS 共用 shadcn/ui 组件体系和发布门禁，但分别拥有组件源码与视觉映射，禁止运行时依赖 Blackline SaaS UI 包。

## 当前实现

平台高保真原型中加入 `signal-canvas` 候选方向，用高对比色块、硬朗边界、海报排版和产品主体展示验证第二家族必须形成真实差异。候选包含产品发布室和创意观察两个原型 Showcase。

这项探索不构成 M3 开工或正式发布决策。家族 ID、视觉方向、shadcn 配置、Showcase 题材和源码结构仍需在 M1、M2 达到依赖条件后锁定；原型记录中的 `web/react/heroui/signal-canvas` 是旧假数据，目标目录条目将使用 `web/react/shadcn/<family-id>`。

## 验证方式

- 独立通过模板规范中的全部自动门禁与人工视觉门禁。
- 与 Blackline SaaS 并排评审，确认用户能清楚区分两套视觉语言。
- 完成固定模板包、预览一致性和真实项目迁移验证。

## 待扩展项

- 确认家族 ID、设计方向和两个 Showcase 题材。
- 确认 shadcn style、底层组件基础、Registry Schema 和稳定依赖范围。
- 公布后根据用户选择与迁移数据决定后续家族方向。
