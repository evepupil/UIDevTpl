# 发布与验收

| 项目 | 内容 |
| --- | --- |
| 模块定位 | 汇总模板平台与两个视觉家族的发布证据，完成公开 V1 验收 |
| 对应代码 | 计划中的 GitHub Actions、Vercel 双 Project、Vercel Blob、迁移测试与发布记录目录 |
| 所属 M 里程碑 | [M4](../roadmap.md#m4) |
| 当前状态 | 未开始 |
| 最近更新时间 | 2026-08-11 |

## 职责与边界

- 汇总自动门禁、人工视觉评审、资产授权和模板包校验结果。
- 校验 shadcn/ui 模板的 `components.json`、Registry Item、底层组件依赖和固定 ZIP 一致性。
- 组织 Codex 与 Claude Code 的 10 个受控迁移任务。
- 验证公开网站、固定版本、缓存、SEO、匿名统计和紧急下架流程。
- 形成可追溯的 V1 发布记录和回退方案。
- 不替代各模块自身的单元测试、构建和实现文档。

## 结构与数据流

```text
平台与模板候选版本
  -> 自动门禁
  -> ZIP / Registry Item 一致性检查
  -> 人工视觉评审
  -> 10 个受控迁移任务
  -> 生产部署与冒烟检查
  -> V1 发布记录
```

## 关键决策

- 10 个迁移任务至少成功 9 个，任何安全类失败直接阻断发布。
- 至少两名评审者独立评分，平均分不低于 4/5，单项不低于 3/5。
- 两个视觉家族分别通过同一套发布标准。
- 固定版本不可变，事故版本使用 `withdrawn` 处理。
- 主站与预览站分别部署为 Vercel Project；模板 ZIP、固定预览归档和校验文件使用 Private Blob，公开参考图使用独立 Public Blob。
- 模板下载通过主站受控路由检查 `availability`，`withdrawn` 关闭入口时不修改 Private Blob 中的审计产物。
- 发布记录在产物上传、校验和线上冒烟全部通过后更新，避免公开半成品版本。
- 固定 ZIP 与 Manifest 是模板版本权威；shadcn Registry Item 从相同源码生成并单独校验，Registry 失败会阻断该版本发布。
- 官网和模板必须通过运行时 UI 依赖隔离检查，禁止模板引用站点 UI 包或可变共享 UI workspace。

## 当前实现

尚无 CI 和公开 V1 发布证据。主站生产环境已部署到 `uidevtpl.chaosyn.com`，并完成旧主站版本的首页、使用说明、模板库、模板详情、固定版本和 HTTPS 冒烟；Blackline SaaS 已通过 Vercel Production 部署 `dpl_5zZy7Ts47EzEYxZ2yZ91bAiaRx5F` 发布到 `preview.chaosyn.com`，Overview、Billing 和 `/component-lab` 均已完成浏览器可见内容、样式和控制台复核。旧 HeroUI `quiet-grid` 草稿已经从源码删除，其验收结果不会继承到 Blackline SaaS；固定生产产物、Registry Item、Blob、下载校验、匿名统计与完整发布流水线仍未纳入公开 V1 证据。验收规则已经写入产品需求与模板规范。

本次线上预览复核发现：三个入口的 HTML、JS 和 CSS 均返回 200，但模板 library 携带的 Base UI CommonJS shim 在浏览器中调用 `require("react")`，导致 React 尚未挂载就白屏。已在模板 library 构建中固定 `use-sync-external-store` 的 ESM external 边界；新部署 `dpl_5zZy7Ts47EzEYxZ2yZ91bAiaRx5F` 已确认 Overview、Billing 和 `/component-lab` 的 DOM、样式和控制台日志均正常。

复核还确认 Preview 必须启用 Tailwind v4 Vite 插件，并扫描模板源码目录；仅加载 CSS 文件会保留基础层，却不会生成 `sidebar-07` 的 utility class。该构建层修复完成后，验收同时检查实际样式和可见交互。

高保真原型阶段已经建立一组早期验证资产：Node 单元测试覆盖筛选、排序、URL 状态和迁移文本生成；Playwright Core 调用本机 Edge 覆盖桌面主流程、iframe Showcase 切换、组件实验室和 390px 无横向溢出；参考截图保存在 `prototype/references/`。这些结果只证明原型行为，不计入 M4 的生产发布证据。

## 验证方式

- 保存每项命令、结果、截图、评分、许可证和迁移报告。
- 检查 Chrome、Edge、Firefox、Safari 和 iOS Safari 的规定版本范围。
- 检查 p75 LCP、INP、CLS、WCAG 2.2 AA 和所有规定视口。
- 演练下载失败、校验失败、预览异常、版本弃用和紧急下架。
- 在干净 npm、pnpm 项目中分别验证 ZIP 迁移与 Registry Item 安装，检查文件差异、依赖和构建结果。
