## 职责与边界

- 规定生产网站、独立预览、共享 Schema、模板源码和发布工具在同一仓库中的边界。
- 规定各模块的基础技术、主版本基线、依赖方向和升级规则。
- 规定固定版本预览、模板包、参考图和校验值的构建与发布顺序。
- 规定 Vercel Project、Vercel Blob 和 GitHub Actions 的职责。
- 不定义视觉家族的具体审美规则，不把账号、投稿和点赞提前纳入 V1 初始数据库范围。

## 结构与数据流

```text
uidevtpl/
  apps/
    web/                     # Next.js 主站，部署为独立 Vercel Project
    preview/                 # Vite MPA 预览站，部署为独立 Vercel Project
  packages/
    schema/                  # Manifest、发布记录和迁移记录 Schema
    design-families/         # 视觉家族权威规则
    templates/               # 各框架真实模板源码、Showcase 和组件实验室
  tooling/
    release/                 # 构建、校验、打包、上传和发布记录更新
  prototype/                 # 迁移完成前保留的高保真交互基准
  pnpm-workspace.yaml
  turbo.json
```

```text
模板源码 + 家族规则 + Manifest
  -> GitHub Actions 自动门禁
  -> Vite MPA 固定版本预览
  -> 模板 ZIP、参考图与 checksums.json
  -> Vercel Blob 不可变对象
  -> preview Vercel Project 固定版本路由
  -> 发布记录最后更新
  -> Next.js 主站显示列表、详情、下载与迁移指令
```

主站只读取 Schema、目录条目和发布记录，不导入模板运行时代码。预览站单独运行模板 Showcase，使用独立域名、iframe sandbox、CSP 和精确的 `postMessage` 来源校验。

## 关键决策

### 仓库与部署

- 使用 pnpm workspaces 管理 monorepo，Turborepo 管理任务依赖、缓存和受影响模块构建。
- `apps/web` 与 `apps/preview` 对应两个独立 Vercel Project；主站建议使用 `uidevtpl.com`，预览站建议使用 `preview.uidevtpl.com`。
- 主站使用 Next.js App Router，负责可抓取页面、固定版本详情、元信息和后续服务端能力。
- 预览站使用 Vite MPA。每个模板版本、Showcase 和组件实验室拥有独立静态入口，避免 SPA 深链回退影响固定 URL。
- GitHub Actions 负责完整发布门禁、固定产物生成和生产发布。Vercel Git 集成可以生成开发预览，生产部署只在门禁通过后由发布任务触发。
- 模板 ZIP、固定版本预览归档和校验文件使用 Vercel Blob Private Storage；公开截图等无执行风险资产使用单独的 Public Storage。对象路径包含模板 ID、版本和内容身份，发布后禁止覆盖。
- 主站下载路由先检查发布记录，再从 Private Blob 流式返回模板包；`withdrawn` 可以关闭公开入口，同时保留不可变审计产物。
- V1 规模下，预览 Project 组装全部已发布固定版本页面；旧版本通过受控发布任务复用 Private Blob 中的已验证构建，不重新编译其源码。

### 技术栈基线

以下主版本是 2026-08-10 的 V1 实现基线。脚手架生成时把具体 minor、patch 写入 `package.json` 和 `pnpm-lock.yaml`。

| 范围 | 选择 | 基线 |
| --- | --- | --- |
| 运行时 | Node.js | `24.x` |
| 包管理器 | pnpm | `10.x` |
| 任务编排 | Turborepo | `2.x` |
| 主站框架 | Next.js App Router | `16.x` |
| UI 运行时 | React | `19.x` |
| 类型系统 | TypeScript strict | `7.x` |
| 主站样式 | Tailwind CSS + CSS Variables | `4.x` |
| 主站交互基础 | Radix Primitives + Lucide | 锁文件固定稳定版 |
| 国际化 | next-intl | `4.x` |
| 预览构建 | Vite MPA | `8.x` |
| 首个模板实现 | HeroUI | `3.x` |
| Schema 校验 | JSON Schema + Ajv | `8.x` |
| 单元测试 | Vitest | `4.x` |
| 浏览器与无障碍 | Playwright + axe-core | `1.x` + `4.x` |

主站 UI 与模板 UI 分开维护。主站使用 Radix Primitives 承载键盘、焦点和浮层能力；HeroUI 只进入声明使用它的模板实现和兼容性测试。

### 数据与持久化

- V1 初始目录、模板和发布数据来自经过 Schema 校验的版本化 JSON，不引入业务数据库。
- Vercel Blob 保存固定文件；发布记录对外提供 UIDevTpl 固定下载路由、大小和 SHA-256，不暴露 Private Blob 凭据与内部 URL。
- 账号、持久化点赞和投稿开放时采用 Neon PostgreSQL + Drizzle ORM；在对应能力进入实现里程碑前不安装数据库依赖。
- 身份服务、匿名统计实现和数据保留期限继续由对应产品决策单独确认。

### 版本与升级

- 根 `package.json` 使用 `engines.node: "24.x"`，并用 `packageManager` 固定 pnpm 的精确版本。
- 平台依赖的精确版本由 `pnpm-lock.yaml` 固定；CI 使用 `pnpm install --frozen-lockfile`。
- 模板 Manifest 记录经过验证的 React、HeroUI、Node.js、样式系统和构建工具兼容范围，不能直接照抄平台依赖版本。
- npm 与 pnpm 的模板兼容测试在隔离的干净项目中运行，不在 monorepo 中维护第二份根锁文件。
- 主版本升级需要通过完整门禁。已经发布的预览和模板包继续使用原构建产物；源码或产物变化通过新模板版本发布。

## 当前实现

- 高保真原型仍使用无构建的 HTML、CSS 和 JavaScript，作为生产迁移的视觉与交互基准。
- 已创建 pnpm workspace 和 Turborepo 根配置，包含 `pnpm-workspace.yaml`、`turbo.json`、严格 TypeScript 基线和唯一的 `pnpm-lock.yaml`。
- `apps/web` 已创建 Next.js App Router 主站骨架，接入 Tailwind CSS、共享视觉家族包和 Schema 包；当前页面是平台目录的可构建占位入口。
- `packages/catalog` 已提供版本化目录 fixture、Category、筛选/排序、路由解析、迁移指令和格式化纯函数；主站不直接读取 `prototype/`。
- `apps/web` 已扩展为可浏览的主站 P0 骨架，包含首页、模板库、分类总览、单分类、最新/固定版本详情、使用说明和账号/投稿预留路由；分类筛选、固定 Showcase 选择和站点语言均由 URL 或请求状态驱动。
- `apps/preview` 已创建 Vite MPA 骨架，包含目录、固定版本预览和组件实验室三个静态入口；`src/main.tsx` 会根据固定深链解析预览入口，`vercel.json` 将版本深链重写到对应 MPA 页面。
- `packages/schema` 已提供 Manifest、目录条目、发布记录和迁移记录类型，以及 Draft 2020-12 + Ajv 校验入口和基础单测。
- `packages/design-families` 已提供 Quiet Grid 家族契约、tokens、组件清单和页面骨架清单。
- `packages/templates/web/react/heroui/quiet-grid` 已创建首个模板包边界和 Manifest 占位，HeroUI 依赖已锁定，真实组件源码仍待实现。
- `tooling/release` 已提供固定版本产物路径计算入口和基础单测，Blob 上传、打包和原子发布仍待实现。
- 主站 Vercel 配置、Blob 产物、CI 发布门禁和固定版本服务端下载路由尚未创建；预览站的固定深链重写配置已加入脚手架。
- 仓库当前没有 Git remote，因此还不能连接 GitHub 与 Vercel 自动部署。

当前主站脚手架验证结果：`@uidevtpl/web` 与 `@uidevtpl/preview` 的 TypeScript 检查、主站与预览生产构建已通过；`@uidevtpl/catalog` 有 4 项纯函数单测，原型继续使用原有的 `npm run verify` 兼容门禁。完整 workspace 门禁仍受并行模板源码的依赖与构建状态影响。

## 验证方式

- 检查所有 workspace 包名称唯一、内部依赖显式声明且不存在循环依赖。
- 运行格式化、静态分析、TypeScript strict、Vitest、Playwright 和生产构建。
- 分别验证 `apps/web` 与 `apps/preview` 的 Vercel 构建，并确认未受影响项目可以跳过。
- 验证模板预览 MPA 的固定版本深链、Vercel 重写、iframe 隔离、CSP、网络白名单和重置通信。
- 验证 Private/Public Blob 权限边界、对象不可覆盖、模板包 SHA-256、固定版本缓存和 `withdrawn` 下架流程。
- 在干净 Vite React 与 Next.js App Router 项目中分别完成 npm、pnpm 安装和构建。
