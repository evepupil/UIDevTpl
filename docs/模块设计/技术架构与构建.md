## 职责与边界

- 规定生产网站、独立预览、共享 Schema、模板源码和发布工具在同一仓库中的边界。
- 规定各模块的基础技术、主版本基线、依赖方向和升级规则。
- 规定固定版本预览、模板包、参考图和校验值的构建与发布顺序。
- 规定 Vercel Project、Vercel Blob 和 GitHub Actions 的职责。
- 不定义视觉家族的具体审美规则，不把账号、投稿和点赞提前纳入 V1 初始数据库范围。

## 结构与数据流

```text
uidevtpl/
  apps/
    web/                     # Next.js 主站，部署为独立 Vercel Project
    preview/                 # Vite MPA 预览站，部署为独立 Vercel Project
  packages/
    schema/                  # Manifest、发布记录和迁移记录 Schema
    design-families/         # 视觉家族权威规则
    templates/               # 各框架真实模板源码、Showcase 和组件实验室
  tooling/
    release/                 # 构建、校验、打包、上传和发布记录更新
  prototype/                 # 迁移完成前保留的高保真交互基准
  pnpm-workspace.yaml
  turbo.json
```

```text
模板源码 + 家族规则 + Manifest
  -> GitHub Actions 自动门禁
  -> Vite MPA 固定版本预览
  -> 模板 ZIP、shadcn Registry Item、参考图与 checksums.json
  -> Vercel Blob 不可变对象
  -> preview Vercel Project 固定版本路由
  -> 发布记录最后更新
  -> Next.js 主站显示列表、详情、下载与迁移指令
```

主站只读取 Schema、目录条目和发布记录，不导入模板运行时代码。预览站单独运行模板 Showcase，使用独立域名、iframe sandbox、CSP 和精确的 `postMessage` 来源校验。

## 关键决策

### 仓库与部署

- 使用 pnpm workspaces 管理 monorepo，Turborepo 管理任务依赖、缓存和受影响模块构建。
- `apps/web` 与 `apps/preview` 对应两个独立 Vercel Project；当前主站生产域名为 `uidevtpl.chaosyn.com`，预览站生产域名为 `preview.chaosyn.com`。
- 主站使用 Next.js App Router，负责可抓取页面、固定版本详情、元信息和后续服务端能力。
- 预览站使用 Vite MPA。每个模板版本、Showcase 和组件实验室拥有独立静态入口，避免 SPA 深链回退影响固定 URL。
- GitHub Actions 负责完整发布门禁、固定产物生成和生产发布。Vercel Git 集成可以生成开发预览，生产部署只在门禁通过后由发布任务触发。
- 模板 ZIP、固定版本预览归档和校验文件使用 Vercel Blob Private Storage；公开截图等无执行风险资产使用单独的 Public Storage。对象路径包含模板 ID、版本和内容身份，发布后禁止覆盖。
- 主站下载路由先检查发布记录，再从 Private Blob 流式返回模板包；`withdrawn` 可以关闭公开入口，同时保留不可变审计产物。
- V1 规模下，预览 Project 组装全部已发布固定版本页面；旧版本通过受控发布任务复用 Private Blob 中的已验证构建，不重新编译其源码。

### 技术栈基线

以下主版本是 2026-08-11 的 V1 实现基线。脚手架生成时把具体 minor、patch 写入 `package.json` 和 `pnpm-lock.yaml`。

| 范围 | 选择 | 基线 |
| --- | --- | --- |
| 运行时 | Node.js | `24.x` |
| 包管理器 | pnpm | `10.x` |
| 任务编排 | Turborepo | `2.x` |
| 主站框架 | Next.js App Router | `16.x` |
| UI 运行时 | React | `19.x` |
| 类型系统 | TypeScript strict | `7.x` |
| 主站样式 | Tailwind CSS + CSS Variables | `4.x` |
| 主站组件层 | shadcn/ui 开放源码 + Lucide | `components.json` 与锁文件固定 |
| 国际化 | next-intl | `4.x` |
| 预览构建 | Vite MPA | `8.x` |
| V1 React 模板体系 | shadcn/ui 开放源码 | CLI、Registry Schema、style 与底层组件依赖精确固定 |
| Schema 校验 | JSON Schema + Ajv | `8.x` |
| 单元测试 | Vitest | `4.x` |
| 浏览器与无障碍 | Playwright + axe-core | `1.x` + `4.x` |

主站 UI 与模板 UI 分开维护。官网拥有自己的 shadcn/ui 组件源码，每个模板实现也拥有独立源码；模板禁止运行时导入官网 UI 包，多个已发布模板也不能依赖一个持续变化的共享 UI workspace。语义 Schema、视觉家族规则、纯数据和生成工具可以共享。

本项目把 shadcn/ui 作为开放源码组件与分发层，能力基线以官方 [Introduction](https://ui.shadcn.com/docs)、[Monorepo](https://ui.shadcn.com/docs/monorepo)、[Theming](https://ui.shadcn.com/docs/theming) 和 [Registry](https://ui.shadcn.com/docs/registry) 文档为准。第三方套件只能提供经过授权的源码输入，不能取代 UIDevTpl 的视觉家族契约和发布门禁。

shadcn/ui 实现需要在 Base UI、Radix 等受支持底层能力中选择一条并固定。V1 的具体选择跟随候选 UI 套件评估结果，单个应用或模板实现内禁止混用。第三方 UI 套件必须先通过商业使用、源码再分发、React 19、Tailwind CSS 4、RSC、键盘操作和无障碍检查。

### 数据与持久化

- V1 初始目录、模板和发布数据来自经过 Schema 校验的版本化 JSON，不引入业务数据库。
- Vercel Blob 保存固定文件；发布记录对外提供 UIDevTpl 固定下载路由、大小和 SHA-256，不暴露 Private Blob 凭据与内部 URL。
- 账号、持久化点赞和投稿开放时采用 Neon PostgreSQL + Drizzle ORM；在对应能力进入实现里程碑前不安装数据库依赖。
- 身份服务、匿名统计实现和数据保留期限继续由对应产品决策单独确认。

### 版本与升级

- 根 `package.json` 使用 `engines.node: "24.x"`，并用 `packageManager` 固定 pnpm 的精确版本。
- 平台依赖的精确版本由 `pnpm-lock.yaml` 固定；CI 使用 `pnpm install --frozen-lockfile`。
- 模板 Manifest、`components.json` 和锁文件共同记录经过验证的 React、shadcn CLI、Registry Schema、底层组件依赖、Node.js、样式系统和构建工具兼容范围，不能直接照抄平台依赖版本。
- 模板 library 构建只将 React、React DOM 和 Base UI 使用的 `use-sync-external-store` shim 作为 ESM 外部依赖，避免把 CommonJS `require` 调用泄漏到浏览器入口；Preview 消费该 library 时由 Vite 继续完成浏览器打包。
- 固定 ZIP 与 Manifest 是版本权威；shadcn Registry Item 从相同源码生成并校验，不能手工维护第二份组件实现。
- shadcn/ui 上游更新通过新模板版本吸收。已经发布的模板继续使用自己的固定源码，不执行原地同步。
- npm 与 pnpm 的模板兼容测试在隔离的干净项目中运行，不在 monorepo 中维护第二份根锁文件。
- 主版本升级需要通过完整门禁。已经发布的预览和模板包继续使用原构建产物；源码或产物变化通过新模板版本发布。

## 当前实现

- 高保真原型仍使用无构建的 HTML、CSS 和 JavaScript，作为生产迁移的视觉与交互基准。
- 已创建 pnpm workspace 和 Turborepo 根配置，包含 `pnpm-workspace.yaml`、`turbo.json`、严格 TypeScript 基线和唯一的 `pnpm-lock.yaml`。
- `apps/web` 已创建 Next.js App Router 主站并接入 Tailwind CSS、共享视觉家族包和 Schema 包；当前 UI 仍以项目自有组件和样式为主，尚未建立 shadcn/ui 组件层。
- `packages/catalog` 已提供版本化目录 fixture、Category、筛选/排序、路由解析、迁移指令和格式化纯函数；主站不直接读取 `prototype/`。
- `apps/web` 已扩展为可浏览的主站 P0 骨架，包含首页、模板库、分类总览、单分类、最新/固定版本详情、使用说明和账号/投稿预留路由；分类筛选、固定 Showcase 选择和站点语言均由 URL 或请求状态驱动。
- `apps/preview` 已创建 Vite MPA 骨架，包含目录、固定版本预览和组件实验室三个静态入口；`src/main.tsx` 会根据固定深链解析预览入口，`vercel.json` 将版本深链重写到对应 MPA 页面。
- `packages/schema` 已提供 Manifest、目录条目、发布记录和迁移记录类型，以及 Draft 2020-12 + Ajv 校验入口和基础单测。
- `packages/schema` 的模板 Manifest 已支持 shadcn 的 `target.library.delivery`、`cliVersion`、`registrySchema`、`style`、`primitive` 和 `iconLibrary` 元数据，并继续对未知字段拒绝。
- `packages/design-families` 已提供 Blackline SaaS 家族契约、tokens、组件清单和页面骨架清单。
- `packages/templates/web/react/shadcn/blackline-saas` 已从官方 Vite 初始化和 `sidebar-07` 产物创建，官方生成的 UI 源码与自有页面组合分开维护；Showcase 所需的 Select、Dialog、Table、Label、Card、Progress 和 Badge 通过同一 shadcn registry 风格补齐。
- Blackline SaaS 的 library build 使用 `dist`，应用演示使用 `dist-app`；Preview 通过直接字体依赖和 Vite 内存适配层消费模板 CSS，避免 workspace 字体资源警告。
- Preview 的生产构建会检查最终 JavaScript 产物不包含 `require` 调用，避免静态资源 HTTP 200 但 React 入口运行时白屏。
- Preview 的 Tailwind v4 Vite 插件通过模板 CSS 的局部 `@source` 扫描模板 TSX，避免 workspace 目录边界导致官方 utility class 缺失；该适配只存在于 Preview 构建层。
- `tooling/release` 已提供固定版本产物路径计算入口和基础单测，Blob 上传、打包和原子发布仍待实现。
- 主站已创建 Vercel Project `uidevtpl`，根目录为 `apps/web`，并通过 `.vercelignore` 保证部署只携带主站及其共享 workspace 依赖；生产域名使用 `uidevtpl.chaosyn.com`，生产变量 `NEXT_PUBLIC_PREVIEW_ORIGIN` 指向独立预览域名。
- 预览站已创建并部署独立 Vercel Project，根目录为 `apps/preview`，安装命令为 `pnpm install --frozen-lockfile`，构建命令为 `pnpm --filter @uidevtpl/preview... build`，输出目录为 `dist`，生产域名为 `preview.chaosyn.com`；`apps/preview/vercel.json` 负责固定版本深链重写。根 `.vercelignore` 已允许预览应用和模板 workspace 进入部署上下文，`apps/preview/.gitignore` 忽略本地 Vercel 配置和环境文件。
- 仓库已连接 GitHub remote `git@github.com:evepupil/UIDevTpl.git`。当前生产发布通过 Vercel CLI 执行，GitHub Actions 自动发布、Blob 产物和固定版本服务端下载路由仍待实现。

当前 Blackline SaaS 模板已通过自身 strict TypeScript、3 项纯函数单测、依赖构建、Vite library build 和 Preview MPA build，并已完成 Vercel Production 部署 `dpl_5zZy7Ts47EzEYxZ2yZ91bAiaRx5F` 的三个入口浏览器验收；HTTP、DOM、样式和控制台检查均通过。固定产物、Blob、发布流水线和公开 V1 完整验收仍待实现。

## 验证方式

- 检查所有 workspace 包名称唯一、内部依赖显式声明且不存在循环依赖。
- 运行格式化、静态分析、TypeScript strict、Vitest、Playwright 和生产构建。
- 分别验证 `apps/web` 与 `apps/preview` 的 Vercel 构建，并确认未受影响项目可以跳过。
- 验证模板预览 MPA 的固定版本深链、Vercel 重写、iframe 隔离、CSP、网络白名单和重置通信。
- 验证 Private/Public Blob 权限边界、对象不可覆盖、模板包 SHA-256、固定版本缓存和 `withdrawn` 下架流程。
- 在干净 Vite React 与 Next.js App Router 项目中分别完成 npm、pnpm 安装和构建。
- 验证官网与模板源码没有共享运行时 UI 依赖，固定 ZIP 与 shadcn Registry Item 的文件清单、依赖和校验值一致。
- 在干净项目中分别验证 ZIP 迁移和 Registry Item 安装，确认 CLI 不会静默覆盖已有文件。
