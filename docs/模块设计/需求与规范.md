## 职责与边界

- 记录已经确认的产品决策、P0/P1 范围和公开 V1 退出标准。
- 记录首版关闭但必须预留的账号、投稿、分享者和互动能力契约。
- 定义视觉家族、模板实现、固定版本、模板包和 AI 迁移的统一契约。
- 约束平台、框架、组件库、运行宿主、许可证和发布状态的表达方式。
- 不承载网站技术架构、具体模板视觉稿和构建流水线实现细节。
- 根目录的 [TEMPLATE_SPEC.md](../../TEMPLATE_SPEC.md) 是可以脱离 UIDevTpl 单独交给其他 AI 的模板开发规范；迁回本仓库时仍以当前 Schema、模块文档和发布门禁为准。

## 结构与数据流

```text
产品需求
  -> 模板规范
  -> 模板平台与模板实现
  -> 自动门禁与人工验收
  -> 公开固定版本
```

产品需求负责说明用户能做什么，模板规范负责说明交付物如何达到发布标准。后续模块文档必须引用这两份基准，出现冲突时先修正文档再继续实现。

## 关键决策

- 模板 ID 使用 `<platform>/<framework>/<library>/<template>`。
- V1 只实现 Web，桌面端和移动端保留模型。
- 一个视觉家族完成内部闭环，公开 V1 至少包含两个视觉家族。
- 模板代码使用 MIT，品牌和第三方资产单独授权。
- 10 个受控迁移任务至少成功 9 个，安全类失败直接阻断发布。
- 网站目录采用独立 `CatalogEntry`，把 Category、分享者和互动数据与不可变模板包隔离。
- 网站首版交付明暗主题和中英文切换，账号与社区投稿通过能力开关逐步开放。
- V1 使用 Vercel 双 Project 与 Vercel Blob；平台技术栈和版本规则由 [技术架构与构建](./技术架构与构建.md) 统一维护。
- 官网与 V1 React 模板统一使用 shadcn/ui；V1 之外仍保留多组件体系模型，固定 ZIP 继续作为权威产物。
