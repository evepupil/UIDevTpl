# 主站体验重设计

| 项目 | 内容 |
| --- | --- |
| 模块定位 | 重建 UIDevTpl 主站的视觉系统、信息架构、页面布局和交互体验 |
| 对应代码 | `apps/web/`、`prototype/`；Catalog、Preview、模板源码和发布工具属于保留边界 |
| 所属 M 里程碑 | [M1](../roadmap.md#m1) |
| 当前状态 | 进行中 |
| 最近更新时间 | 2026-08-15 |

## 当前阶段

主站已进入全量 UI 重构准备阶段。产品事实记录在仓库根目录的 [`PRODUCT.md`](../../PRODUCT.md)，当前代码和旧原型只用于行为盘点、回退和识别反面模式，不再提供视觉权威。

新界面设计尚未开始。下一阶段必须先通过 Impeccable 的 `shape` 完成页面任务与边界讨论，再进入 `new-work` 选择全新的视觉世界。方向确认前不创建 `DESIGN.md`，不删除旧主站代码，也不把旧视觉逐步修补进新实现。

## 职责与边界

本模块负责：

- 主站品牌表达、页面构图、信息层级、导航和跨页面体验。
- 主站主题 Token、基础组件、交互状态和响应式规则。
- 首页、模板库、分类、模板详情、迁移指南和能力保留页的展示与操作流程。
- 搜索、筛选、预览、迁移和匿名偏好在界面层的承载方式。

本模块不修改：

- `@uidevtpl/catalog` 与 `@uidevtpl/schema` 的模板身份、分类、固定版本和发布数据契约。
- `apps/preview/` 的独立预览运行时和固定深链。
- `packages/templates/` 下已经发布或正在验收的模板源码。
- `tooling/release/`、Vercel 双 Project、Blob 产物和发布门禁。
- M2 已完成的 `blackline-saas` 模板实现。

## 已确认的产品路径

首要用户是使用 AI 编程工具开发产品、具备基本开发能力但缺少完整视觉系统的独立开发者和前端开发者。

主路径保持连续：

1. 匿名浏览并筛选模板。
2. 检查真实预览、固定版本和技术兼容性。
3. 复制固定版本迁移指令交给目标项目中的 AI。

V1 暂不支持用户上传模板、真实投稿、账号系统和跨设备同步。数据契约、能力网关和稳定路由保留扩展位置；关闭状态不能产生伪写入请求。

## 重构策略

本次采用主站 UI 全量重写。旧代码用于提取行为约束和验证路径，布局、样式、视觉组件、文案层级和页面组合不继续继承。

删除动作设置在设计确认之后，顺序如下：

1. 完成 `PRODUCT.md`。
2. 通过 `shape` 确认主站任务、范围、状态和反目标。
3. 通过 `new-work` 选择新视觉世界和页面结构。
4. 记录方向合同并获得用户确认。
5. 批量删除旧展示实现，先建立 Token 与基础组件，再实现业务页面。

这样可以保证删除范围可恢复，也能避免在旧结构中继续叠加新视觉。

## 结构与数据流

新实现继续沿用以下产品数据流：

```text
@uidevtpl/catalog
  -> 路由参数与 URL 查询解析
  -> 页面级 view model
  -> 主站业务组件
  -> 模板详情 / Preview URL / 固定版本迁移指令
```

重构时把查询解析、路径生成、版本绑定和复制状态从展示 JSX 中分离。页面组件只负责当前页面的内容组织与交互，核心筛选、路径和版本计算继续由纯函数与现有单元测试保护。

主站与模板运行时继续隔离：主站只读取 Catalog 和 Preview URL，iframe 指向独立 Preview Project，主站构建不能导入模板 UI 组件。

## 关键决策

1. `UIDevTpl Signal Desk` 视觉方向已废弃，仅作为历史反面参考。
2. 新主站采用全量 UI 重写，不在旧布局和旧 CSS 上渐进美化。
3. 产品功能、路由、固定版本和发布边界保持稳定，视觉重构不能重新打开已确认架构决策。
4. V1 主路径保持匿名；用户上传、真实投稿和账号能力暂不开放，只保留可扩展的数据与路由边界。
5. 新设计必须使用 Impeccable 的 `shape` 与 `new-work` 流程，经用户确认后才进入代码删除和页面实现。
6. 新界面先建立统一 Token 与基础组件，再按首页、模板库、分类、详情和指南顺序实现。
7. `DESIGN.md` 在新视觉世界形成并通过完成评审后记录，不能从旧界面自动提取为新基线。

## 当前实现

当前 `prototype/` 和 `apps/web/` 仍保留在仓库中，保证生产行为可检查、历史可回退。它们覆盖首页、模板库、分类、固定版本详情、预览、迁移指南、匿名偏好和能力保留页，但视觉与页面结构均待替换。

当前混合在 JSX 中的筛选参数解析、版本路由、Preview URL、迁移指令、剪贴板降级和匿名点赞逻辑已经列入行为保留清单。正式删除前需要先为新的职责边界补齐或沿用核心逻辑测试。

- 核心筛选、固定路由、Preview URL 和迁移指令继续通过单元测试。
- TypeScript、格式化、静态分析、测试和生产构建全部通过。
- 桌面、平板和手机完成一轮批量视觉检查、一轮集中修复和最多一轮确认。
- Impeccable detector、完成评审和设计系统归档全部关闭后，才删除替代完成的旧实现。
