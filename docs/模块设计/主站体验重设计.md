| 项目 | 内容 |
| --- | --- |
| 模块定位 | 为 UIDevTpl 主站定义独立的品牌、信息架构、页面布局和交互基线 |
| 对应代码 | `prototype/`、`apps/web/`；原型先验证布局和功能位置，生产页面后续迁移到 Next.js + shadcn/ui |

| 当前状态 | 进行中 |
| 最近更新时间 | 2026-08-11 |

## 设计目标

UIDevTpl 主站服务一条连续路径：用户先判断模板是否适合当前项目，再检查真实界面和兼容信息，最后把固定版本的迁移指令交给 AI。页面需要帮助用户快速做决定，展示真实模板内容，并让版本、技术栈和迁移入口始终可见。

本轮重设计清空旧原型目录中的页面、预览样式、伪模板资产和参考截图，重新建立低保真 HTML / CSS / JavaScript 原型。新原型只验证页面布局、信息层级和功能位置，生产主站不继承旧原型的视觉顺序和 CSS 结构。Catalog 数据、固定路由、真实预览、筛选、语言、主题、点赞和迁移指令仍属于产品能力范围。

## 当前原型

`prototype/index.html` 是当前主站布局基准，直接打开即可查看。原型覆盖 7 个视图：首页发现工作台、模板库、用途目录、模板详情、迁移指南和登录 / 注册 / 投稿三个保留入口。模板详情改为整页结构：顶部是面包屑、模板名、固定版本徽标、作者与技术栈；主操作是复制给 AI、打开独立预览和组件实验室；左侧是预览工作台，包含 Showcase 切换、桌面 / 平板 / 手机视口和就绪 / 加载 / 错误三种预览状态；预览下方用 Tabs 切换 Showcase、组件、Tokens、迁移；右侧是版本检查栏，展示固定版本、构建工具、包管理器、产物大小、SHA-256、许可证、兼容性和主题能力。

`prototype/data.js` 集中维护分类、模板和 zh / EN 文案，作为经典脚本先加载；`prototype/app.js` 负责状态、客户端视图路由、搜索、筛选、排序、点赞、主题、语言、复制指令和详情工作台交互；`prototype/styles.css` 只用线框和少量品牌色表达层级，不模拟最终模板视觉。`prototype/browser-smoke.cjs` 使用 Edge 验证桌面与 390px 移动布局，覆盖搜索 → 筛选 → 详情页 → 保留入口的主流程与无横向溢出。

## 设计基线

### preset 的作用

`apps/web/components.json` 已安装用户指定的 shadcn/ui preset：

- 风格：`base-vega`
- 颜色基线：`neutral`
- 图标：`lucide`
- 字体：`Noto Sans`
- 交互基础：preset 当前选择 `Base UI`
- 主题入口：`background`、`foreground`、`card`、`muted`、`primary`、`accent`、`border`、`ring` 等语义变量

preset 负责组件的几何、状态、主题变量和可访问交互基础。UIDevTpl 自己决定品牌、页面构图、内容密度、模板预览表达和文案，不复用任何参考产品的品牌、页面文案或具体 DOM 结构。

### 视觉方向：UIDevTpl Signal Desk

主站采用“产品工作台 + 模板目录”的方向，整体克制、明快、可扫描：

- 画布使用温和的中性灰白，正文使用石墨黑，边界使用低对比度灰线。
- 品牌强调使用一枚高辨识度的荧光黄绿色，主要用于当前选中、发布状态和关键行动；喜欢、警告和失败使用珊瑚色与琥珀色区分。
- 不使用渐变、光晕、装饰性圆点和无意义的背景插画。
- 页面区块采用开放式布局；卡片只用于重复的模板条目、筛选面板和明确需要边界的工具。
- 统一使用不超过 8px 的圆角和稳定的预览比例。标题服务于检索与判断，保持工具页面的尺寸，不做营销页式超大 Hero。
- 模板预览承担主要视觉表达。缩略图优先来自真实 Showcase 截图或预览站，不再用四块伪 UI 拼贴表示分类。
- Light / Dark 使用完整语义变量，网站主题与模板自身主题能力分开声明。

### 组件使用原则

官网使用 `components/ui/` 下的本地 shadcn/ui 源码，业务组件放在 `components/site/`、`components/catalog/`、`components/template/` 等目录。官网与模板运行时不共享 UI 包。

首批计划使用的 shadcn/ui 组件：

- `Button`、`Input`、`Badge`、`Separator`、`Tooltip`
- `Command`、`DropdownMenu`、`Select`、`ToggleGroup`
- `Tabs`、`ScrollArea`、`Sheet`、`Dialog`
- `Card`、`Breadcrumb`、`Accordion`、`Skeleton`

同一页面只固定一套底层交互实现。官网沿用 preset 选择的 Base UI，清理旧页面直接依赖的临时对话框实现后再进入完整验收。

## 信息架构

### 顶部导航

桌面端使用 56px 高的产品栏：

1. 左侧放 UIDevTpl 品牌与版本状态入口。
2. 中间放 `模板库`、`分类`、`使用指南` 三个入口，当前页面使用清晰的 active 状态。
3. 右侧放全局搜索触发器、提交入口、语言、主题和登录入口。

全局搜索使用 `Command`，支持模板名、模板 ID、框架、组件库和分类。键盘快捷键只作为触发辅助，不在页面中大段解释。移动端将导航收进 `Sheet`，搜索保持在首屏可触达位置。

### 路由保留与职责

| 路由 | 新职责 |
| --- | --- |
| `/` | 模板发现工作台：快速搜索、当前精选系统、用途索引和最新模板 |
| `/templates` | 模板库：筛选、排序、版本状态和模板网格 |
| `/categories` | 用途索引：按产品任务浏览，而非视觉拼贴浏览 |
| `/categories/:slug` | 单用途结果：继承模板库筛选与 URL 状态 |
| `/templates/:platform/:framework/:library/:slug` | 最新稳定版本详情 |
| `/templates/:platform/:framework/:library/:slug/:version` | 固定版本详情，所有预览、产物和迁移指令绑定该版本 |
| `/docs/use-with-ai` | 迁移流程、目录约定、校验和失败处理 |
| `/login`、`/signup`、`/submit` | 能力关闭时的明确占位页，保留稳定入口和产品契约 |

## 首页布局

首页直接进入可用的模板发现流程，不做独立营销首页。

### 1. 工作台头部

页面顶部使用两列工作区：

- 左侧是短标题、当前模板数量和全局搜索输入。文案强调“从真实界面系统开始”，不使用抽象口号。
- 右侧是当前精选模板的真实预览切片，旁边显示模板 ID、版本、框架和“复制给 AI”入口。

右侧区域只承担一个精选模板的判断任务，保持清晰的预览边界，不嵌套多个装饰卡片。桌面端形成入口和样例的平衡，手机端改为上下结构，搜索排在预览前。

### 2. 用途索引

用横向索引条展示 `应用与游戏`、`营销与落地页`、`数据看板`、`组件与交互`、`登录与注册`、`内容与作品集`。每个条目只保留图标、名称、模板数量和箭头，点击后进入对应分类页。

分类入口不再用四块缩略图拼贴。用户需要的是用途判断和结果数量，真实模板内容留给模板库展示。

### 3. 最新系统

下方使用稳定比例的模板预览网格：

- 第一条展示 1 个横向精选模板和 2 个常规模板，形成主次关系。
- 之后按 3 列展示最新模板；卡片底部显示作者、浏览量、点赞、平台 / 框架 / 组件库和版本状态。
- 卡片上的主要动作是打开详情和点赞，复制迁移指令放在详情页，避免列表出现多个同等级按钮。

### 4. 迁移提示

首页底部保留一条轻量的流程入口，说明“查看真实预览 -> 复制固定版本指令 -> 交给 AI 迁移”。使用 `Steps` 式的横向结构和一个进入指南的按钮，避免大面积宣传横幅。

## 模板库布局

`/templates` 采用典型的目录工作区：

- 顶部是页面标题、当前结果数和搜索输入。
- 左侧是 240px 筛选栏，包含平台、框架、组件库、用途和排序；筛选变化同步到 URL。
- 右侧是工具栏和模板网格，工具栏显示当前筛选、清除入口和排序选择。
- 桌面端筛选栏保持可见，手机端通过 `Sheet` 打开；搜索和结果数在手机端固定在顶部。
- 空状态提供当前查询摘要、清除筛选和返回全部模板三个动作。

模板条目采用统一结构：真实预览、状态 / 版本标记、名称、模板 ID、作者、技术栈、指标和详情入口。预览区域稳定使用 16:10，防止加载和 hover 改变网格尺寸。

## 分类页布局

`/categories` 改为用途目录页：每一行包含编号、图标、用途名称、短说明、模板数量、最近更新模板和进入箭头。宽屏使用两栏索引，移动端单列。

单分类页沿用同一套模板库工作区，只额外显示分类说明和返回分类索引的面包屑。分类筛选不会复制另一套交互逻辑。

## 模板详情布局

详情页的核心是“检查一套系统”，结构按判断顺序排列：

1. 面包屑、模板名称、固定版本、作者、平台 / 框架 / 组件库和主题能力。
2. 主操作：`复制给 AI`、`打开独立预览`、`组件实验室`。
3. 左侧大预览工作台，右侧版本检查栏。预览工作台拥有 Showcase 切换、桌面 / 平板 / 手机视口切换和加载 / 错误状态。
4. 预览下方使用 `Tabs` 切换 `Showcase`、`组件`、`Tokens`、`迁移`，避免把所有信息垂直堆在一个长页面里。
5. 右侧检查栏展示固定版本、构建工具、包管理器、产物大小、SHA-256、许可证和兼容声明。
6. 迁移页签显示完整指令、固定版本指纹和复制按钮，复制完成后给出短暂确认反馈。

移动端先显示身份与主要操作，再显示预览；版本检查栏移动到预览后；复制操作在滚动过程中保持易于重新触达。iframe 预览仍使用独立 Preview Project，不把模板运行时组件注入主站。

## 使用指南与保留页

`/docs/use-with-ai` 使用四步流程：确认项目、下载并校验、保存到 `.uidevtpl/`、迁移并运行门禁。每一步配一个简洁的代码或文件路径示例，失败时明确停止条件。

登录、注册和投稿页面使用同一套页面壳，只展示当前能力状态、入口用途和返回模板库动作。页面不模拟尚未存在的账号功能。

## 保留的产品能力

重设计只改变主站体验层，以下能力和数据契约继续保留：

- `@uidevtpl/catalog` 的模板、分类、作者、指标、Showcase、组件清单和迁移字段。
- 模板列表搜索、筛选、排序和 URL 状态恢复。
- 分类总览、单分类结果和空状态。
- 最新版本与固定版本路由。
- 内嵌预览、独立预览、Showcase 选择和常用视口。
- 迁移指令生成、复制反馈和固定版本身份绑定。
- Light / Dark、中文 / English、点赞和能力关闭时的预留入口。

## 明确弃用的原型表达

- 居中 Hero + 分类拼贴 + 精选网格的固定首页顺序。
- 四块伪 UI 缩略图组成的 Category 卡片。
- 依赖 `TemplateVisual` CSS 绘制模板页面的主要列表表达。
- 通过大面积边框、阴影和多个嵌套卡片制造层次。
- 把主导航、分享、语言、主题、登录和注册全部放在同一条拥挤的右侧操作区。

原型保留用于回看旧交互的历史记录，新的实现以本文件和当前 Catalog 契约为准。旧页面组件会在新页面验收通过后分批删除，避免一次改动同时破坏预览和路由。

## 实现拆分

确认设计后按以下顺序实现：

1. 将 preset 的主题变量整理为 UIDevTpl 的语义 token，建立官网自己的 UI 组件目录。
2. 重写产品栏、搜索 Command、主题 / 语言入口和移动端 Sheet。
3. 重写首页工作台、用途索引和模板网格。
4. 重写模板库筛选工作区、分类索引和空状态。
5. 重写详情预览工作台、版本检查栏和迁移页签。
6. 迁移使用指南和能力关闭页面，删除旧视觉类名及伪预览实现。
7. 在桌面、平板、手机视口完成人工检查，再运行项目门禁。

## 验收口径

- 页面不再依赖原型的布局顺序、拼贴卡片和旧 CSS 视觉类名。
- 首页首屏能直接搜索、打开精选模板或进入用途索引。
- 模板库筛选可通过 URL 恢复，手机端不出现横向溢出。
- 详情页能在同一版本下切换 Showcase、视口和独立预览，并复制对应迁移指令。
- 主站 UI 使用本地 shadcn/ui 源码，官网与模板运行时 UI 依赖边界清楚。
- Light / Dark、中文 / English、点赞、空状态、预览错误和复制反馈均有可理解状态。
- 真实预览内容承担视觉表达，页面不使用装饰性渐变、光晕或无意义伪截图。
- 通过 TypeScript、单元测试、构建和原型兼容性门禁；页面视觉问题通过规定视口人工验收。
